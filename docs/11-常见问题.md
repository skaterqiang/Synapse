# 11. 常见问题

[← 返回目录](README.md)

## 11.1 启动与安装

**Q：macOS 打开应用提示「已损坏」或被 Gatekeeper 拦截？**

应用未使用 Developer ID 签名。右键点击应用图标 → 选择「打开」即可。开发模式下 `npm start` 会自动执行 ad-hoc 签名（`scripts/ensure-mac-sign.js`），一般不会遇到此问题。

**Q：Windows 安装包被 SmartScreen 拦截？**

安装包未签名。点「更多信息 → 仍要运行」。

**Q：能在 Windows 上打包 macOS 版本吗？**

不能。跨平台限制，`npm run dist:mac` 必须在 macOS 上执行。

**Q：`npm start` 后窗口空白？**

用 `npm start -- --kb-debug` 启动（会自动打开开发者工具），查看控制台报错。主进程日志会输出在终端。

## 11.2 模型与 AI

**Q：提示「尚未配置 API Key」？**

到「设置 → 模型配置」填写 API Key 并保存。这是除纯笔记编辑外所有 AI 功能的前提。

**Q：支持哪些模型服务？**

两类：**阿里云百炼（DashScope）**与本地 **Ollama**。两者均走兼容 OpenAI `/chat/completions` 的接口格式。

**Q：本地模型（Ollama）怎么配？**

服务商选 Ollama（Base URL 自动填 `http://localhost:11434/v1`），模型名填你已 pull 的模型（如 `qwen2.5`），**API Key 可以留空**。

**Q：接口返回 429（速率限制）怎么办？**

降低「设置 → 作业 → 总并发任务数量」（如设为 1–2）。

**Q：报错「模型返回无法解析」？**

模型没按要求输出 JSON。可能原因与对策：
- 模型能力不足 → 换用更强的模型
- 自定义提示词破坏了 JSON 约定 → 到「提示词管理」点「恢复默认」
- 偶发问题 → 直接重试

**Q：为什么 AI 反问我问题而不直接回答？**

这是**澄清问题机制**：任务开放且缺关键约束时，AI 会先确认方向/格式/范围。整个任务最多问一次。选择选项后即会正式作答。详见 [3.6](03-AI问答.md#36-澄清问题机制)。

**Q：AI 说「已联网搜索」但结果明显不对？**

请确认 🧩 菜单里对应 MCP 服务器处于**参与**状态（未被去除）。若工具装载失败，界面会下发告警步骤；若模型只口头说要搜索却没实际调用工具，系统会自动催促一次真实调用。

## 11.3 领域与历史管线

**Q：图谱抽取时领域总是判定为 general？**

说明领域预匹配未命中。检查：
- 是否已创建特定领域模版（只有 general 时不会触发匹配）
- 模版的**关键词**是否有足够区分度
- 可调整「提示词管理 → 图谱 · 领域匹配」

**Q：之前的「吸收」和「LLM Wiki」去哪了？**

吸收（把来源编译为 Wiki 页面）与 Wiki 问答/体检目前作为**内部管线**保留，当前界面已无发起入口；历史吸收作业仍会在「作业管理」中显示。若你此前已吸收过资料，生成的 Wiki 页面仍在 `<数据根目录>/llmwiki/` 下，可正常查看与用 git 管理。

**Q：能手动编辑 llmwiki 下的 Wiki 页面吗？**

可以，它们就是普通 Markdown 文件，位于 `<数据根目录>/llmwiki/`。但**不要手改 `index.md`**——它由应用确定性重建，会被覆盖。

**Q：llmwiki 能用 git 管理吗？**

非常适合。`llmwiki/` 全是 Markdown 文件，可单独初始化 git 仓库获得完整版本历史。

## 11.4 知识图谱

**Q：抽取后图谱是空的？**

- 确认来源有实质文本内容
- 查看作业管理页该作业的错误信息
- 若报「模型未抽取到任何节点」，尝试缩小范围或更换更强的模型

**Q：图谱节点太碎/太笼统？**

调整「本体定义」收紧实体类与谓词，再重新抽取；也可定制「提示词管理 → 图谱 · 本体抽取」。结构化约束（本体定义）比改提示词更稳定可控。

**Q：KG 问答说找不到相关实体？**

系统有三层兜底（LLM 抽取 → 问题直接含节点名 → 分词评分召回）。若仍无结果，说明图谱中确实没有相关内容，需要先抽取相应资料。

**Q：重新抽取会覆盖已有图谱吗？**

不会全量覆盖。节点按规范化名称去重、边按三元组去重，属于**增量合并**。若要彻底重建，先用「整体图谱 → 🧹 清空」。

## 11.5 数据与迁移

**Q：数据存在哪里？**

统一数据根目录（默认项目下 `data/`）：`knowledge.db`（知识库数据）、`app.db`（模型 API Key、MCP 与 Skills 配置）、`note/`（笔记 Markdown）、`artifacts/`（技能产物）；历史吸收产物在 `llmwiki/`（Wiki 页面）。

**Q：怎么备份？**

直接复制整个数据根目录即可。因为笔记等都是普通文件，数据库包含知识库 `knowledge.db` 与应用配置 `app.db` 两个 `.db` 文件。

**Q：怎么迁移到新电脑/新位置？**

- 换位置：「设置 → 存储 → 数据根目录」填新路径，重启生效
- 换电脑：拷贝整个数据根目录到新机器，在设置中指向它

**Q：修改数据根目录后数据不见了？**

数据根目录修改**需要重启**才生效。重启后若仍异常，检查新目录是否可写，以及原目录数据是否完整。

**Q：笔记能用其他编辑器编辑吗？**

可以。笔记是 `<数据根目录>/note/` 下的标准 Markdown 文件（带 YAML frontmatter 存元数据）。你在文件系统中新建的目录与 `.md` 文件，Synapse 启动时会自动识别并纳入目录树。

**Q：删除原始文件引用会删掉我的本机文件吗？**

不会。本机文件采用引用式管理，「移除」/「解除」只解除引用关系。只有 `raw/_auto/` 下的自动生成文件才会被真正删除。

## 11.6 性能与配额

**Q：怎么控制 token 消耗？**

- 降低「来源内容截断阈值」（设置 → 作业）
- 问答时只勾选必要的数据源
- 提取笔记 / 图谱时按需分批，而非一次性批量处理超大目录

**Q：批量提取笔记 / 抽取图谱很慢？**

提高「总并发任务数量」（注意模型服务的速率限制）。作业采用逐来源独立处理，本身已针对速度做了优化。

**Q：应用占用内存较高？**

数据库采用 sql.js（内存数据库），整库常驻内存。个人知识库规模下影响有限；若图谱或作业历史过大，可清理历史或减少「作业历史保留条数」。

## 11.7 界面操作

**Q：怎么调整各栏宽度？**

拖拽栏之间的分隔条，**双击**分隔条恢复默认宽度。宽度偏好会记忆。

**Q：笔记列表栏怎么收起/恢复？**

点列表标题栏的 `«` 收起；收起后会出现恢复按钮。打开设置、作业、图谱等整页视图时列表栏会自动让位。

**Q：找不到「提取笔记 / 提取知识图谱」按钮？**

这些入口统一为**右键菜单**。在原始文件行、目录、笔记卡片上右键即可；右键侧边栏「📝 笔记」或「🗄 原始文件」入口可批量提取。

**Q：预览里的代码块看不清？**

代码块使用 atom-one-dark 深色主题并已与背景色匹配。若显示异常，尝试重启应用以重新加载样式资源。

## 11.8 获取帮助

- 应用菜单 **Help → GitHub 仓库（Synapse）** 可打开项目仓库
- `npm start -- --kb-debug` 启动可打开开发者工具查看渲染层报错
- 主进程日志输出在启动 Synapse 的终端窗口
