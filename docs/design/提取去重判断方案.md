## 二、核心：用什么方法判断「已提取过」 ✅

**标识 = 来源路径，新鲜度 = mtime（修改时间）**，复用现成机制，不引入新存储、不算内容 hash：

```
判断(key):
  rec = kv["raw.ingested"][key]          # key = local:绝对路径 / raw:相对路径 / url:链接
  无 rec            → 未提取，需要提取
  local: 文件:
      当前mtime > rec.mtime  → 文件被改过，需重新提取（stale）
      当前mtime ≤ rec.mtime  → 已提取且未变，跳过（fresh）
  raw: / url:       → 有记录即视为已提取（转存副本/链接内容不变）
```

**为什么用 mtime 而不用内容 hash**：
- mtime 是 `stat` 系统调用，O(1) 零 IO 开销；hash 要读完整个文件
- 文件被编辑后 mtime 几乎必然变化，足够可靠
- 与 extract-cache 的判断口径一致（`extractCacheKey` 也是 path+size+mtime）

**三种产物各自的判重口径**：

| 产物 | 判重依据 | 重复时行为 |
|---|---|---|
| 文件正文（OCR/解析） | `extractCacheKey`=sha1(path)+size+mtime | 已有 ✅ 命中缓存直接用（files.js 836） |
| **笔记** | kv `raw.ingested` + 笔记 `source` 字段 | 笔记本就「同 source 原地更新」不重复（store.js 432）；补「已提取则跳过提交」 |
| **知识图谱** | kv `raw.ingested` + 图节点 `sources[]` | 图节点已记录来源 label（graph.js 236/248），可按来源增量 |

## 三、待您拍板的两处产品行为 ❓

### ❓A. 检测到「已提取且未修改」时，默认怎么做？

| 选项 | 行为 | 适合 |
|---|---|---|
| **A1（我的推荐）** | 默认**跳过**，toast 提示「N 个已提取过已跳过」，并给「仍要重新提取」入口 | 省 Token、最贴您「检查是否已提取过」的诉求 |
| A2 | 弹窗列出，逐个勾选哪些重提 | 想精细控制时 |
| A3 | 只标注不拦截，照常全提 | 只想有个提醒 |

### ❓B. 知识图谱的判重粒度？

图谱和笔记不同：笔记是一对一覆盖，图谱是**多源融合进同一张图**，整图跳过会丢「新源+旧源融合」的场景。

| 选项 | 行为 | 风险 |
|---|---|---|
| **B1（我的推荐）** | **按来源增量**：已入图且未变的源跳过，只抽取新增/变更的源，增量合并进图 | 需统一「图节点 sources 的 label」与「kv 的 key」口径，改动中等 |
| B2 | 所选来源集合**全部**已提取且未变才整体跳过，否则全量重抽 | 简单，但只要加一个文件就全量重抽，费 Token |
| B3 | 本期只做「提取笔记」判重，图谱暂不动 | 最稳，图谱后续单做 |
