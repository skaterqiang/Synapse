# 课程知识图谱发布前的校验环节

根据发布流程规范，内容从提交到分发共经 **提交 → 解析 → 校验 → 序列化 → 分发** 五个环节，其中"校验"是发布前的核心质量关卡 [02-发布流程规范](import:mtzh4zwcm9xwaz)。校验依赖一组明确的 **校验规则**（图谱：`校验 —依赖→ 校验规则`）。

## 一、一致性校验（结构性检查）

解析阶段将 Turtle 源本体转为结构化模型（类、层级、属性、个体）后，校验阶段需确认：[02-发布流程规范](import:mtzh4zwcm9xwaz)

- **类层级不得成环**——继承链不能形成循环。
- **属性定义域 / 值域必须指向已声明的类**——例如"包含章节"的定义域是课程、值域是章节，不能指向未声明的类。
- **个体必须归属某个类**——不允许存在游离的实例。

## 二、业务校验规则

| 规则 | 说明 |
|---|---|
| 课程 ↔ 教师 | 每门课程**有且仅有一位**授课教师 |
| 先修关系 | 不得**自反**（一门课不能是自己的先修课），不得**成环** |
| 章节归属 | 章节必须归属于某门课程，**孤立项不予发布** |
| 知识点归属 | 知识点必须归属于某个章节 |

这些规则在图谱中也有对应关系：`课程 —包含→ 章节`、`章节 —包含→ 知识点`、`知识点 —属于→ 主题`、`课程 —相关→ 教师` [02-发布流程规范](import:mtzh4zwcm9xwaz)。

## 三、往返一致性校验（Round-Trip）

序列化导出后，还需进行**往返一致性**检查：将导出的 RDF/XML 重新导入，类数量、属性数量、个体数量必须与源模型完全一致，核心公理不得丢失。发布失败时回滚到上一个版本号（如 v2026.09）并通知作者修正 [02-发布流程规范](import:mtzh4zwcm9xwaz) [01-课程知识图谱本体](import:mtzh4zw51621bf)。

## 四、责任分工

- **发布平台**：执行解析、校验、序列化、分发。
- **内容作者**：编写课程本体、维护知识点描述。
- **学科审核员**：审核学科归属与先修关系合理性 [02-发布流程规范](import:mtzh4zwcm9xwaz)。

> 简言之，校验环节 = **结构一致性检查 + 四项业务规则检查 + 往返一致性验证**，三者全部通过后才进入序列化与分发。
