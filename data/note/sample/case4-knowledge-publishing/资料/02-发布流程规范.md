# 知识内容发布流程规范

## 一、发布管线

内容从作者提交到下游系统消费，经过五个环节：

1. **提交**：作者用 Turtle 语法手写课程本体，提交到内容仓库。
2. **解析**：发布平台解析 Turtle 为结构化本体模型（类、层级、属性、个体）。
3. **校验**：对模型做一致性校验——类层级不得成环、属性的定义域/值域必须指向已声明的类、个体必须归属某个类。
4. **序列化**：校验通过后导出为 Turtle、RDF/XML、Functional Syntax 三种格式。
5. **分发**：搜索系统消费 Turtle，推荐系统消费 RDF/XML，学习路径系统消费 Functional Syntax。

## 二、校验规则

- 每门课程必须有且仅有一位授课教师。
- 先修课程关系不得自反（一门课不能是自己的先修课），不得成环。
- 章节必须归属于某门课程，孤立的章节不予发布。
- 知识点必须归属于某个章节。

## 三、版本与回滚

每次发布生成一个版本号（如 v2026.09）。发布失败时回滚到上一个版本，并通知作者修正。往返一致性是发布的硬性要求：把导出的 RDF/XML 重新导入后，类数量、属性数量、个体数量必须与源模型一致。

## 四、责任分工

| 角色 | 职责 |
|---|---|
| 内容作者 | 编写课程本体，维护知识点描述 |
| 发布平台 | 解析、校验、序列化、分发 |
| 学科审核员 | 审核课程内容的学科归属与先修关系合理性 |
| 下游系统负责人 | 确认本系统能正确消费对应格式 |
