# 临床数据中心医疗本体层建设说明

## 一、背景

某省级三甲医院临床数据中心建设医疗知识图谱本体层，需与国际医学本体生态对齐（BFO / OGMS / DOID / ChEBI 风格）。本体文件由领域专家用 Turtle 维护，发布为 RDF/XML（OWL 标准交换格式）供 LIS（检验）、PACS（影像）、EMR（电子病历）等子系统消费，同时支持从 RDF/XML 重新导入做一致性校验。

## 二、临床核心骨架

四类核心概念构成临床骨架：

- **疾病（Disease）**：如 2型糖尿病、原发性高血压、社区获得性肺炎。疾病按科室与病因分类。
- **症状（Symptom）**：如 多饮、多尿、体重下降、发热、咽痛。症状是患者主观感受或客观体征。
- **药物（Drug）**：如 二甲双胍、格列美脲、阿莫西林。药物含有效成分，有剂型与给药途径。
- **检查（Examination）**：如 空腹血糖、糖化血红蛋白、口服葡萄糖耐量试验、胸部X线。检查分检验类与影像类。

## 三、临床关系

| 关系 | 说明 |
|---|---|
| 疾病 表现为 症状 | 一种疾病有多个典型症状 |
| 疾病 确诊依据 检查 | 确诊某疾病需要做的检查项目 |
| 药物 治疗 疾病 | 药物的适应症 |
| 药物 含有 成分 | 药物的有效化学成分 |
| 检查 检出 指标异常 | 检查结果指向的异常指标 |
| 疾病 并发 疾病 | 并发症关系 |

## 四、与顶层本体的对齐

按 BFO 的划分：疾病是「倾向（disposition）」——患者身体的一种病理倾向；症状是「性质（quality）」——依附于患者身体的可观察属性；药物是「物质实体（material_entity）」；检查是「过程（process）」——有始有终的诊疗活动；患者的「角色（role）」是依情境获得的（如「糖尿病患者」这一角色）。检查过程实现（realizes）疾病的诊断倾向。

## 五、交换与校验要求

本体发布为 RDF/XML 后，子系统导入时必须通过一致性校验：类层级无环、属性定义域/值域合法、不相交类（如疾病与药物）不得共享实例。校验失败则拒绝导入并回报错误明细。
