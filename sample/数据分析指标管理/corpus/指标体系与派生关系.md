# 指标体系与派生关系

指标体系分三层：**原子指标 → 派生指标 → 复合指标**。原子指标直接由事实表的某个度量列聚合得到；派生/复合指标由其它指标按公式计算。指标"依赖"关系是传递的——派生指标依赖的原子指标一旦被修改，会沿依赖链传导到所有上层指标。

## 原子指标（直接来自明细聚合）

| 原子指标 | 口径 | 来源事实表 | 计算 |
|---|---|---|---|
| 下单订单数 | 有效订单笔数 | dwd_order_detail | COUNT(order_id) |
| 下单金额 | 有效订单金额合计 | dwd_order_detail | SUM(amount) |
| 支付订单数 | status=paid 的订单笔数 | dwd_order_detail | COUNT(*) WHERE status='paid' |
| 支付金额 | status=paid 的金额合计 | dwd_order_detail | SUM(amount) WHERE status='paid' |
| 退款金额 | status=refunded 的金额合计 | dwd_order_detail | SUM(amount) WHERE status='refunded' |
| 支付用户数 | 有支付行为的去重用户数 | dwd_order_detail | COUNT(DISTINCT user_id) WHERE status='paid' |
| 下单用户数 | 有下单行为的去重用户数 | dwd_order_detail | COUNT(DISTINCT user_id) |
| 复购用户数 | 下单≥2 笔的去重用户数 | dwd_order_detail | COUNT(DISTINCT user_id) HAVING COUNT(*)>=2 |

## 派生指标（由原子指标按公式得到）

| 派生指标 | 公式 | 直接依赖 |
|---|---|---|
| 支付成功率 | 支付订单数 / 下单订单数 | 支付订单数、下单订单数 |
| 客单价 | 支付金额 / 支付用户数 | 支付金额、支付用户数 |
| 退款率 | 退款订单数 / 下单订单数 | 下单订单数（+ 退款金额对应的退款订单数） |
| 复购率 | 复购用户数 / 下单用户数 | 复购用户数、下单用户数 |

## 复合指标（派生指标再组合）

| 复合指标 | 公式 | 直接依赖 |
|---|---|---|
| ARPU（人均产出） | GMV / 下单用户数 | 下单金额、下单用户数 |
| 客单价健康度 | 客单价 × 支付成功率 | 客单价、支付成功率 |

## 指标引用的维度

派生/复合指标在按维度下钻时引用 DIM 维表：客单价、支付成功率可按 `dim_city`（城市）、`dim_user.channel`（渠道）拆分；所有日粒度指标引用 `dim_date`。**维表是指标的横向依赖**：更换 `dim_city` 的城市划分口径，会影响所有"引用维度=dim_city"的指标。

## 依赖传导（传递性）

```
下单金额 ─┐
          ├─(依赖)→ ARPU
下单用户数 ┘
支付金额 ─┐
          ├─(依赖)→ 客单价 ─┐
支付用户数 ┘                ├─(依赖)→ 客单价健康度
支付订单数 ─┐              │
            ├─(依赖)→ 支付成功率 ─┘
下单订单数 ─┘
```

因"依赖"具传递性：删除"下单订单数"，将波及 支付成功率 与 客单价健康度（后者经 支付成功率 间接依赖）；"下单订单数"又是"支付成功率"口径变更的上游。
