# 数据血缘与依赖

血缘描述"一张表/一个字段的数据从哪来"。表级血缘沿 ODS→DWD→DWS→ADM 传递，具有传递性：`adm_overview_1d` 加工自 `dws_trade_city_1d`，后者加工自 `dwd_order_detail`，故 ADM 间接血缘到 DWD。字段级血缘把口径落到列，是"修改某字段影响哪些指标"的定位依据。

## 表级血缘

| 目标表 | 加工自（来源） | 加工动作 |
|---|---|---|
| dwd_order_detail | ods_order_raw | 去重、丢弃空用户/负金额、状态归一 |
| dwd_payment_detail | ods_payment_raw | 过滤 pay_status='success'、关联订单 |
| dws_trade_user_1d | dwd_order_detail | 按 user_id × order_date 聚合 |
| dws_trade_city_1d | dwd_order_detail | 按 city_id × order_date 聚合 |
| adm_overview_1d | dws_trade_city_1d、dwd_order_detail | 汇总日粒度指标、算派生指标 |
| dim_user | ods_user_raw | 拉链表去重、退化城市 |

横向引用：dwd/dws/adm 均 JOIN dim_user、dim_city、dim_date。

## 字段级血缘（关键度量列）

```
ods_order_raw.amount ──(去重求和)→ dwd_order_detail.amount
dwd_order_detail.amount ──(SUM)→ 下单金额 ──(比率)→ 客单价、ARPU
dwd_order_detail.status='paid' ──(COUNT)→ 支付订单数 ──→ 支付成功率
dwd_order_detail.user_id ──(DISTINCT)→ 支付用户数 ──→ 客单价
ods_payment_raw.pay_amount ──→ dwd_payment_detail.pay_amount ──(核对)→ 支付金额
```

## 血缘到指标的桥接

事实表列先聚合为**原子指标**，原子指标再派生为**派生指标**。因此一次"字段口径变更"会沿 `字段 → 原子指标 → 派生/复合指标` 逐级放大。示例：若把 `dwd_order_detail.status` 的取值从 `{paid,unpaid,refunded}` 扩展出 `partial_refund`，则所有以 status 过滤的原子指标（支付订单数、支付金额、退款金额）都要重定义，进而影响支付成功率、客单价、退款率。

## 维表血缘的特殊性

维表（dim_city/dim_user/dim_date）不被"加工链"传递，而是被各层"引用"。维表内容变更（如城市大区重划）不会改变血缘结构，但会**改变所有引用该维度的指标的分组结果**——属于横向影响，与纵向血缘影响需分别评估。
