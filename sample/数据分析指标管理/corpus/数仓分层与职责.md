# 数仓分层与职责

数据仓库按"数据流向与加工深度"分为五层：ODS、DWD、DWS、ADM（ADS）与 DIM。每一层职责单一、向下依赖上一层，形成可追溯的加工链。

## ODS 贴源层（Operational Data Store）

ODS 层**贴近业务系统原样落地**，只做最小限度的清洗（去空、字段对齐），保留脏数据用于追溯与重算。本样例包含三张贴源表：`ods_order_raw`（订单）、`ods_payment_raw`（支付）、`ods_user_raw`（用户）。ODS 层的典型特征是**允许重复、允许非法值**——例如 `ods_order_raw` 中存在重复订单号 1001、负金额订单 9001、非法状态订单 9002。

## DWD 明细层（Data Warehouse Detail）

DWD 层对 ODS 做**清洗、去重、维度退化**，产出"一行一事实"的明细事实表。本样例的加工规则是：按 `order_id` 去重、丢弃 `user_id` 为空或金额为负的脏行、将订单状态归一为 `paid/unpaid/refunded`。产出 `dwd_order_detail`、`dwd_payment_detail`。DWD 层保留业务粒度，是上层所有汇总的**共同事实基线**。

## DWS 汇总层（Data Warehouse Summary）

DWS 层按"分析主体 + 时间周期"对 DWD 做**轻度聚合**，产出可复用的宽事实。本样例按"用户/城市 × 日"聚合，产出 `dws_trade_user_1d`、`dws_trade_city_1d`，度量包含下单订单数、下单金额、支付订单数、支付金额。DWS 层的价值在于**一次聚合、多处复用**，避免每个指标都从明细重算。

## ADM 应用层（Application Data Mart）

ADM 层面向具体报表与指标产品，从 DWS（必要时回到 DWD）加工出**结果宽表**。本样例 `adm_overview_1d` 每日给出下单订单数、GMV、支付订单数、支付金额、支付用户数、支付成功率、客单价、退款金额、退款率。ADM 层是指标出口，直接与 BI/看板对接。

## DIM 维度层（Dimension）

DIM 层存放**一致性维度**，被明细层与汇总层横向关联（JOIN）。本样例含 `dim_user`、`dim_city`、`dim_date` 三张维表。DIM 不随事实层层传递，而是被各层"引用"，因此维表变更会影响所有引用它的事实表与指标。

## 加工链走向

```
ODS(ods_order_raw / ods_payment_raw / ods_user_raw)
   │  清洗·去重·状态归一
   ▼
DWD(dwd_order_detail / dwd_payment_detail) ──引用── DIM(dim_user/dim_city/dim_date)
   │  按用户/城市 × 日 聚合
   ▼
DWS(dws_trade_user_1d / dws_trade_city_1d)
   │  计算派生指标、拼结果宽表
   ▼
ADM(adm_overview_1d)
```
