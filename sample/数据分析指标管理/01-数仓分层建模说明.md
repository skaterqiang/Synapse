# 数仓分层建模说明

主题域：**电商交易分析**。数据仓库按加工深度分五层，`warehouse/dw.sqlite` 是一个用 `sql.js` 真实构建、可用任意 SQLite 客户端打开的样例库。

## 一、分层与职责

| 层 | 定位 | 样例表 | 加工动作 |
|---|---|---|---|
| ODS 贴源层 | 原样落地、允许脏数据 | `ods_order_raw`、`ods_payment_raw`、`ods_user_raw` | 最小清洗、保留重复/非法值 |
| DWD 明细层 | 一行一事实的清洗层 | `dwd_order_detail`、`dwd_payment_detail` | 去重、丢弃空用户/负金额、状态归一 |
| DWS 汇总层 | 主体×周期轻度聚合 | `dws_trade_user_1d`、`dws_trade_city_1d` | 按用户/城市 × 日聚合 |
| ADM 应用层 | 面向报表的结果宽表 | `adm_overview_1d` | 汇总日指标、计算派生指标 |
| DIM 维度层 | 一致性维度，被各层引用 | `dim_user`、`dim_city`、`dim_date` | 拉链/去重、供 JOIN |

## 二、加工链走向

```
ODS(ods_order_raw / ods_payment_raw / ods_user_raw)
   │  清洗·去重·状态归一
   ▼
DWD(dwd_order_detail / dwd_payment_detail) ──引用── DIM(dim_user / dim_city / dim_date)
   │  按用户/城市 × 日 聚合
   ▼
DWS(dws_trade_user_1d / dws_trade_city_1d)
   │  计算派生指标、拼结果宽表
   ▼
ADM(adm_overview_1d)
```

关键约定：**纵向血缘**（ODS→DWD→DWS→ADM，`加工自` 具传递性）决定"源表口径变更会波及哪些下游表/指标"；**横向引用**（各层 JOIN DIM）决定"维表变更会影响哪些分组结果"。二者需分别评估。

## 三、样例事实基线

DWD 有效订单共 8 笔（订单号 1001~1008），据此各层一致：

| 指标 | 值 | 口径 |
|---|---|---|
| 下单订单数 | 8 | 有效订单笔数 |
| GMV（下单金额） | 2500 | SUM(amount) |
| 支付订单数 | 6 | status=paid |
| 支付金额 | 2150 | SUM(amount) where paid |
| 支付用户数 | 5 | 去重 paid 用户 |
| 客单价 | 430 | 支付金额 / 支付用户数 |
| 支付成功率 | 0.75 | 支付订单数 / 下单订单数 |
| 退款金额 | 150 | status=refunded |
| 退款率 | 0.125 | 退款订单数 / 下单订单数 |
| 复购率 | 0.6 | 下单≥2 笔用户 / 下单用户数（u1/u2/u3） |

ODS 中额外保留了重复订单 1001、负金额脏行 9001、非法状态脏行 9002，用于演示清洗——清洗后 DWD 恰好只剩 8 笔。

## 四、如何重建与核对

在 `warehouse/` 目录执行：

```bash
node build-warehouse.js
```

脚本会读取 `schema.sql`（建表）、`seed.sql`（灌数），生成 `dw.sqlite`，并运行 `query.sql` 打印：

- 各层行数总览（ODS 23 / DWD 14 / DWS 9 / ADM 2 / DIM 11）；
- 从 DWD 复算的全域原子/派生指标；
- DWD 分日复算值与 ADM 预置值逐行对照（一致）；
- 清洗验证：`ods_order_raw` 11 行 → `dwd_order_detail` 8 行。

末尾输出 `[check] ... PASS` 表示各层口径自洽。
