本样例以「电商交易分析」为主题，端到端演示 Synapse 的四步链路：**数仓数据 → 抽取语料 → 抽取知识图谱 → 用图谱校验新需求与指标影响**。全部产物已预置在本目录，无需运行大模型即可查阅。

## 目录内容

| 子目录 / 文件 | 对应环节 | 说明 |
|---|---|---|
| `warehouse/` | 1.1 | 真实 SQLite 数仓（ODS/DWD/DWS/ADM/DIM 五层）+ 建表/灌数/复算脚本 |
| `corpus/` | 1.2 | 从数仓知识抽取出的 3 篇结构化语料（Markdown） |
| `ontology/dw-metric.ttl` | 1.3 | 领域本体（可"导入 OWL"为体系 `owl:dw-metric`） |
| `graph/dw-metric-graph.json` | 1.3 | 按本体抽取的知识图谱（节点/边与应用同构） |
| `tools/validate-impact.js` | 1.4 | 图谱影响面校验脚本（沿传递谓词 BFS） |
| `01 ~ 03` 三篇笔记 | 全程 | 分层建模 / 指标口径 / 需求影响校验 |

## 如何动手体验

1. **看数仓分层**：进入 `warehouse/`，运行 `node build-warehouse.js` 会重新生成 `dw.sqlite` 并打印各层行数与指标复算核对（详见笔记 01）。
2. **导入本体到应用**：在 Synapse「本体定义 → 导入 OWL」选择 `ontology/dw-metric.ttl`，得到 `owl:dw-metric` 体系。
3. **看图谱与影响面**：笔记 03 给出删除/修改某指标的预期影响面；运行 `node tools/validate-impact.js` 会沿 `dependsOn`、`processedFrom` 两条传递谓词计算实际影响面并自检（应全部 PASS）。
4. 也可把 `graph/dw-metric-graph.json` 视作"抽取结果快照"，其节点 `sources` 回填到 `corpus/` 与数仓笔记，形成"笔记→语料→图谱"可追溯闭环。

## 阅读顺序建议

`01-数仓分层建模说明` → `02-核心指标定义与口径` → `03-新需求校验与指标影响分析`。
