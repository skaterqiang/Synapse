# 核心指标定义与口径

指标体系三层：**原子指标 → 派生指标 → 复合指标**。"依赖"关系具传递性，是指标影响分析的骨架。

## 一、原子指标（直接来自 `dwd_order_detail` 聚合）

| 原子指标 | 口径（SQL） |
|---|---|
| 下单订单数 | `COUNT(order_id)` |
| 下单金额 | `SUM(amount)`（即 GMV） |
| 支付订单数 | `COUNT(*) WHERE status='paid'` |
| 支付金额 | `SUM(amount) WHERE status='paid'` |
| 退款金额 | `SUM(amount) WHERE status='refunded'` |
| 支付用户数 | `COUNT(DISTINCT user_id) WHERE status='paid'` |
| 下单用户数 | `COUNT(DISTINCT user_id)` |
| 复购用户数 | 按 user_id 分组 `HAVING COUNT(*)>=2` 的用户数 |

## 二、派生指标（公式）

| 派生指标 | 公式 | 直接依赖 |
|---|---|---|
| 支付成功率 | 支付订单数 / 下单订单数 | 支付订单数、下单订单数 |
| 客单价 | 支付金额 / 支付用户数 | 支付金额、支付用户数 |
| 退款率 | 退款订单数 / 下单订单数 | 退款金额（口径）、下单订单数 |
| 复购率 | 复购用户数 / 下单用户数 | 复购用户数、下单用户数 |

## 三、复合指标（再组合）

| 复合指标 | 公式 | 直接依赖 |
|---|---|---|
| ARPU | GMV / 下单用户数 | 下单金额、下单用户数 |
| 客单价健康度 | 客单价 × 支付成功率 | 客单价、支付成功率 |

## 四、维度引用（横向依赖）

- 客单价、支付成功率支持按 `dim_city`（城市）、`dim_user.channel`（渠道）下钻；
- 所有日粒度指标引用 `dim_date`；
- 更换维表口径（如城市大区重划）不改变血缘结构，但会改变所有"引用该维度"指标的分组结果。

## 五、依赖传递图

```
下单金额 ─┐
          ├─(依赖)→ ARPU
下单用户数 ┘
支付金额 ─┐
          ├─(依赖)→ 客单价 ─┐
支付用户数 ┘                ├─(依赖)→ 客单价健康度
支付订单数 ─┐              │
            ├─(依赖)→ 支付成功率 ─┘
下单订单数 ─┘
```

因"依赖"传递：`客单价健康度` 经 `支付成功率` 间接依赖 `下单订单数`——删除 `下单订单数` 会波及 `客单价健康度`（见笔记 03 场景 A）。

## 六、口径一致性红线

1. 每个派生/复合指标必须显式声明其依赖的原子指标，禁止在报表层"临时改公式"；
2. 原子指标必须 `取自表` 指向合法事实表（本例统一指向 `dwd_order_detail`）；
3. 同一原子指标被多个派生指标复用时，其口径变更需评估全部下游——这正是知识图谱影响面分析的用途。
