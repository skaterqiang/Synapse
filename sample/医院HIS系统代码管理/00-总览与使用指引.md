本样例以真实开源医院信息系统 **TANGKUO/HIS**（Spring Cloud + Spring Boot + MyBatis + Vue，Apache-2.0）为素材，端到端演示 Synapse 的链路：**真实代码 → 抽取语料 → 抽取知识图谱 → 用图谱校验新 HIS 需求与功能增删改查影响**。全部产物已预置在本目录，无需运行大模型即可查阅。

## 目录内容

| 子目录 / 文件 | 对应环节 | 说明 |
|---|---|---|
| `code/` | 2.1 | 从上游仓库截取的 22 个代表性源码文件（实体/控制器/服务/模块 pom）+ `SOURCE.md`（来源与许可） |
| `corpus/` | 2.2 | 从代码与业务流抽取的 3 篇结构化语料（功能模块 / 业务流 / 数据模型） |
| `ontology/his.ttl` | 2.2 | HIS 领域本体（可“导入 OWL”为体系 `owl:his`） |
| `ontology/medical-undergrad.ttl` | 2.2 | 医学本科核心概念本体（91 类 / 20 谓词，体系 `owl:medical-undergrad`），覆盖解剖/生理/病理/诊断/内科/外科/妇产/儿科/药理等本科核心课程概念层，与 HIS 数据实体通过 `rdfs:seeAlso` 松耦合 |
| `资料/` | 补充 | 8 门本科核心课程的课程资料卡（原创章节级知识框架 + 对齐 `mu:` 本体的概念清单 + 标准教材书目 + 合法开放获取链接），不含教材全文；可作为抽取语料源 |
| `graph/his-graph.json` | 2.2 | 按本体抽取的知识图谱（35 节点 / 边与应用同构） |
| `tools/validate-impact.js` | 2.3 | 图谱影响面校验脚本（沿传递谓词 BFS） |
| `01 ~ 03` 三篇笔记 | 全程 | 系统架构 / 业务流与依赖 / 需求影响校验 |

## 如何动手体验

1. **看代码来源**：进入 `code/`，先读 `SOURCE.md`（上游仓库、commit、Apache-2.0、模块前缀→业务域对照）。
2. **导入本体到应用**：在 Synapse「本体定义 → 导入 OWL」选择 `ontology/his.ttl`，得到 `owl:his` 体系；再导入 `ontology/medical-undergrad.ttl`，得到 `owl:medical-undergrad` 体系（91 类 / 20 谓词，含传递谓词 `hasAnatomicalPart`、`locatedInStructure`）。两套体系可共存，抽取时 AI 按领域自动选择对应体系。
3. **看图谱与影响面**：笔记 03 给出下线/改造某功能、修改某数据实体的预期影响面；运行 `node tools/validate-impact.js` 会沿 `dependsOnFunction`、`callsService` 传递谓词（及 `readsWrites` 反查）计算实际影响面并自检（应全部 PASS）。
4. 也可把 `graph/his-graph.json` 视作"抽取结果快照"，其节点 `sources` 回填到 `code/` 文件路径与 `corpus/` 语料，形成"代码→语料→图谱"可追溯闭环。

## 阅读顺序建议

`01-HIS系统功能与架构` → `02-核心业务流与模块依赖` → `03-新需求校验与功能影响分析`。
